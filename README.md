# dsh-comfyui-panel

**状态：规划中（先做调研）· Status: planned, pending a scope decision.** 尚无可用版本。

> DSH 的 **ComfyUI 面板**：在会话里驱动 ComfyUI 工作流、浏览与迭代生成结果。

## 先说清楚：这个方向已经有玩家

生态目录里已存在：

| 项目 | 星 | 状态 |
|---|---|---|
| `fandc520/dsh-comfyui` | **70★** | 已发布 npm，名字已被占 |
| `wbin0001/dsh-comfyui-canvas` | 8★ | 画布方向 |

所以**本仓库的第一步不是写代码，而是先调研这两个实现**，然后回答一个问题：

> **它们没做好的地方是什么？**

如果答案是"没什么没做好的"，这个仓库就应该**关掉**——重复建设对谁都没好处。

## 目前倾向的方向（待调研后确认）

- **面板化**：把 ComfyUI 的产出铺在 DSH 里浏览与挑选，而不是切窗口
- **工作流与 DSH 的上下文打通**：让 agent 知道"上一个工作流用了什么参数、产出在哪"，从而能接着改
- **本地优先**：ComfyUI 本来就在本地，不做云端中转

## 不做什么

- **不重写 ComfyUI**，也不做它的替代前端
- **不代管模型文件下载**
- **不与上游争抢 `dsh-comfyui` 这个名字**：本项目用 `-panel` 后缀以明确区分
